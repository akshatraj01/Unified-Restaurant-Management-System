# Unified Restaurant Management System (URMS)

A modular, menu-driven restaurant operations management project developed in **C** using structures, functions, binary file handling, and standard C libraries.

## Project objectives

URMS demonstrates how core restaurant activities can be organized in one application. It includes food menu maintenance, customer records, order processing, billing calculations, kitchen order status, ingredient inventory, employee records, table reservations, reports, and backup utilities.

## Main modules

| Module | Capabilities |
|---|---|
| Authentication | Demo role login for admin, manager, and cashier |
| Food menu | Add, view, update, and change item availability |
| Customers | Register and list customer records |
| Orders & kitchen | Create multi-item orders, calculate totals, view history, update status |
| Inventory | Record ingredients, view low-stock alerts, restock |
| Employees | Add employees, view records, mark attendance |
| Reservations | Create and view table reservations |
| Reports | Revenue summary and item sales counts |
| Backup | Copy data files to and from the backups directory |

## Technology and C concepts

- C11
- Structures and arrays
- Functions and modular programming
- Binary file handling (`fread`, `fwrite`)

## Build instructions

### GCC

From the project root:

```bash
gcc -std=c11 -Wall -Wextra -pedantic -Iinclude src/*.c -o urms
```

Run:

```bash
./urms
```

On Windows:

```powershell
gcc -std=c11 -Wall -Wextra -pedantic -Iinclude src/*.c -o urms.exe
.\urms.exe
```

Alternatively, if `make` is installed:

```bash
make
```

## Data storage

The application creates the `data/` directory automatically. Records are stored in binary files. The audit trail is appended to `data/audit.log`.

Binary files are compiler/platform dependent and are generated by running the program. Do not assume a `.dat` file is portable between different compiler ABIs. The source code is the authoritative project content.

## Important implementation notes

- The tax rate in `src/order.c` is an illustrative 5% value. Update it according to the applicable tax rules before real use.
- The current order module stores selected food items and calculates the bill. It does not yet deduct recipe ingredients from stock; the inventory module currently supports ingredient records, low-stock alerts, and manual restocking.
- Reservation records are stored, but overlapping table reservations are not yet automatically rejected.
- The role login demonstrates role selection but the sample main menu does not enforce per-module authorization. Add centralized permission checks before treating it as a secure access-control system.
- This is an academic demonstration project, not production restaurant software.
